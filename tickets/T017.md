# Solution C learned grasp-affordance scorer

Rank several geometry-safe planar grasp candidates from the rendered RGBD observation. Execute the selected proposal through the existing deterministic tracker, interception planner, FANUC controller, contact gate, PLC boundary, verification, recovery, and audit.

## Inputs

- YOLO26 instance mask and confidence from the rendered overhead RGB image
- metric rendered depth and calibrated camera model
- tracked product pose, velocity, identity, observation age, and intercept time
- candidate point, local mask geometry, estimated width, boundary clearance, jaw yaw, and product-relative offset
- product recipe and configured gripper geometry

## Outputs

- a ranked list of geometry-safe `VisionGraspProposal` values
- predicted bilateral-contact, retained-lift, slip, excessive-contact, and delivery outcomes per candidate
- scalar learned score, uncertainty, model identity, and selected rank
- an abstain or deterministic-fallback decision when the model or evidence is invalid

## Data source

Training rows must come from complete Isaac Sim Scene 2 cycles using actual rendered RGBD, the FANUC articulation controller, conveyor motion, bilateral PhysX contact, the compliant-gripper approximation, PLC state, and final delivery verification. A row must retain the candidate features plus contact, lift, retention, slip, excessive-contact proxy, delivery, motion-limit, collision, and terminal outcomes. Simulator-independent labels cannot satisfy this ticket.

## Training or fitting method

Fit the smallest auditable regularized linear or logistic candidate-ranking model that separates successful retained delivery from contact, retention, slip, excessive-contact, or delivery failures. Split complete seeded cycles into fit and held-out groups. Record feature normalization, coefficients, model hash, data hashes, seed groups, and held-out metrics. Do not install another learning framework.

## Inference boundary

The model may rank only candidates already inside the mask and geometric clearance envelope. It may not create a target, change a track identity, change interception timing, bypass freshness or reach checks, command the articulation, change PLC state, or relax any motion, collision, verification, recovery, or audit threshold.

## Fallback behavior

If the model file, schema, feature set, checksum, confidence, or score margin is invalid, use `mask_pca_clearance_v2` or reject before commitment according to configuration. Any downstream deterministic gate failure rejects or recovers exactly as A or B does.

## Pass criteria

- Focused unit tests cover candidate geometry, deterministic ranking, serialization, corrupt-model fallback, low-margin fallback, and no unsafe-candidate promotion.
- Held-out seeded simulator trials produce a nonempty dataset with every required outcome field and no train and held-out seed overlap.
- Solution C completes at least one full Solution A cycle and one full Solution B cycle with learned ranking active.
- Both cycles save the model identity, all candidate scores, selected rank, RGB, depth, grasp visualization, trajectory, event trace, contact evidence, PLC transitions, video, USD, metrics, and fail-closed audit.
- A seeded comparison against `mask_pca_clearance_v2` reports success, grasp confirmation, retained lift, slip, excessive contact, interception timing, delivery position and yaw, cycle time, recovery, collision and motion-limit violations, and bounded replay.
- The ordinary suite and documented release gate pass without weakened thresholds.

## Fail criteria

- Any control input uses the simulator product oracle.
- Candidate labels come only from proxy math or unexecuted trajectories.
- A learned score bypasses deterministic gates.
- Required evidence is missing or empty.
- Held-out execution regresses a safety, motion, collision, recovery, or audit gate.
