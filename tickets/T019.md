# Solution E bounded learned contact-segment skill

Learn only the close, stabilize, slip-correction, reorientation, and release segment. Run replay and shadow evaluation first. Permit bounded execution only after held-out seeded Scene 2 rollouts pass.

## Inputs

- short history of rendered RGBD features and the stable product track
- measured FANUC joints and TCP, jaw position, drive effort proxy, bilateral PhysX contact, retention distance, and slip estimate
- target-frame error, current explicit skill state, recipe, PLC state, and emergency-stop state

## Outputs

- short bounded task-space or jaw action chunks for close, stabilize, slip correction, reorientation, or release
- action uncertainty, abstention, intervention, and fallback reason
- shadow prediction, applied command, and deterministic-gate result

## Data source

Use demonstrations or residual targets generated inside the complete Scene 2 cell with the rendered sensors, actual FANUC articulation control, PhysX contact, conveyor motion, compliant-gripper approximation, PLC state, and final verification. Real force or tactile workpiece data remains required before any hardware-validity claim.

## Training or fitting method

Start with behavior cloning or a bounded residual model using complete-cycle seeded demonstrations. Split by complete seed and scenario. Record the action normalization, horizon, loss, data hashes, model hash, replay metrics, and held-out rollouts. No software installation is permitted.

## Inference boundary

The learned skill may act only inside an explicit contact-segment state and a bounded task-space or jaw envelope. Deterministic freshness, reach, timing, joint, velocity, acceleration, collision, force-proxy, PLC, emergency-stop, verification, recovery, and audit logic remains authoritative.

## Fallback behavior

On uncertainty, invalid state, stale input, limit proximity, unexpected contact, retention loss, or model error, stop applying learned residuals and return to the deterministic contact sequence, recover, reject, or safe-stop as the supervisor requires.

## Pass criteria

- C and D are complete and remain green.
- Offline replay and simulation shadow evaluation pass before bounded execution is enabled.
- Held-out seeded bounded-action rollouts cover nominal close and stabilize, injected slip correction, reorientation, release, unexpected contact, stale input, and emergency stop.
- A and B full cycles retain every evidence and audit gate and show no collision, motion-limit, PLC, or recovery regression.
- Reports include success, grasp confirmation, retained lift, slip, excessive contact, interception timing, delivery position and yaw, cycle time, recovery, intervention, collision, motion limits, and bounded replay.

## Fail criteria

- The model is promoted from replay or shadow mode without passing held-out bounded rollouts.
- Learned commands bypass deterministic limits or supervisor state.
- Simulator-independent proxy output is presented as integrated evidence.
- Hardware validity is claimed without representative physical force or tactile data.

## Exact simulator evidence

- synchronized demonstration dataset and split manifest
- model JSON or checkpoint with training record and hashes
- replay, shadow, and bounded-execution summaries
- complete Scene 2 RGBD, skill visualization, action chunks, trajectory, contact, PLC, trace, video, USD, metrics, audit, and failure evidence
- one-command replay or shadow launcher and, only after promotion, one-command bounded execution launcher

## Physical-data blocker

The current simulator has uncalibrated drive effort, rigid workpieces, approximate friction, no real tactile array, and no measured tissue damage response. A simulator E slice may validate software boundaries and shadow or bounded behavior only. It cannot establish learned-policy hardware validity until representative physical force, tactile, slip, damage, and recovery data exist.
