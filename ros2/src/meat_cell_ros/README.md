# meat_cell_ros

ROS 2 Humble nodes for the pork leg cell's grasp pipeline, and the simulated cell exposed as ROS 2
interfaces. The cell logic is not here: it is `meat_cell_sim` (`belt_state`, `intercept`,
`grasp_action`, `grasp_policy`, `grasp_execution`, `scara_kinematics`), so the simulator and these
nodes run the same code.

## The split that makes it work on any arm

```
mujoco_bridge (simulation) or camera + perception computer (real cell)
                                         ->  leg/perception    (LegPerception, belt frame)
mujoco_bridge or the belt encoder        ->  joint_states belt joint
belt_state_node                          ->  belt/state        (BeltState: travel, speed, acceleration)
grasp_policy_node  (deterministic or learned, by parameter)
                                         ->  grasp/action      (GraspAction: point on the leg, jaw line, tilt, opening)
grasp_executor_node  (one per arm, config/<arm>.yaml)
    intercept plan -> timed tool waypoints -> IK service -> FollowJointTrajectory + GripperCommand
```

Nothing upstream of the executor names a robot. A new arm is a config file, a description in
`cell_description` and, if MoveIt's IK plugins cannot solve it, an IK node on the same
`GetPositionIK` interface. An arm that cannot do what an action asks refuses with a declared outcome
(`tool_cannot_tilt` on the SR-20iA) before anything moves.

## Packages in this workspace

`meat_cell_ros` is robot-agnostic and imports only numpy-only modules (`robotics.core` and the
application's `grasping`), which `tests/test_layering.py` enforces. Everything that needs the simulator
or this cell's arm geometry is in `pork_leg_cell_ros`.

| Package | What it holds |
|---|---|
| `meat_cell_msgs` | `LegPerception`, `BeltState`, `GraspAction`, action `ExecuteGrasp` |
| `meat_cell_ros` | belt state, grasp policy and grasp executor nodes, per-arm executor configs, `grasp_pipeline.launch.py` |
| `pork_leg_cell_ros` | this cell's adapters: `mujoco_bridge_node` (the simulated cell), `scara_ik_node` (SR-20iA closed-form IK), `sim_grasp.launch.py`, `test/check_moveit_ik.py` |
| `cell_description` | URDF for the UR20 and SR-20iA as mounted in the cell, with the jaw gripper's `tcp`; generated by `applications.pork_leg_alignment.sim.robot_description` and checked against MuJoCo |
| `cell_moveit_config` | MoveIt 2 config per arm: SRDF, KDL kinematics (UR20), joint limits, OMPL, controllers, `move_group.launch.py` |

## Nodes, topics and QoS

| Node | Subscribes | Publishes / serves | QoS |
|---|---|---|---|
| `mujoco_bridge` | none | `/clock`, `joint_states`, `leg/perception`, `sim/grasp_report`; actions `<arm>_arm_controller/follow_joint_trajectory`, `gripper_controller/gripper_cmd` | clock and joints best effort depth 10; the rest reliable |
| `belt_state` | `joint_states` (belt joint) | `belt/state` | in: sensor data; out: reliable, depth 10 |
| `grasp_policy` | `leg/perception` | `grasp/action` | reliable, depth 10 |
| `grasp_executor` | `belt/state`, `joint_states`, `grasp/action` | action `execute_grasp`; calls the IK service, trajectory and gripper actions | reliable, depth 10; joint states sensor data |
| `scara_ik` | none | service `scara/compute_ik` (`GetPositionIK`, closed form) | services |

Frames: `world` is the cell world (REP 103); each arm's URDF roots at `world` and ends at `tcp`.
`robot_state_publisher` publishes the arm's TF; the executor reads `world` to `tcp`. Everything in
simulation runs on `/clock`.

## Environment

Humble from apt on this PC lacks MoveIt's planner and controller plugins, and installing them needs
`sudo`. The working install, made without `sudo` on 2026-09-15, is the RoboStack conda environment
`ros_moveit` (Python 3.12, MoveIt 2.5.9, ros2_control, UR description, and MuJoCo 3.12.0 plus the
simulator's Python dependencies via pip):

```
env -u PYTHONPATH bash
source ~/miniconda3/etc/profile.d/conda.sh && conda activate ros_moveit
cd ~/robot-learning-lab/ros2 && colcon build && source install/setup.bash
export PYTHONPATH=$PYTHONPATH:~/robot-learning-lab/src MUJOCO_GL=egl
```

`env -u PYTHONPATH` matters: a shell that has sourced `/opt/ros/humble` leaks Python 3.10 paths into
the 3.12 environment.

## Checks

- `python3 src/meat_cell_ros/test/smoke_grasp_pipeline.py`: policy node answers a leg with the
  rule's grasp; a SCARA executor refuses a tilt; no belt state means no plan. No MoveIt needed.
- `ros2 launch cell_moveit_config move_group.launch.py arm:=ur20` with a `/clock`, then
  `python3 src/pork_leg_cell_ros/test/check_moveit_ik.py`: MoveIt's IK for three tool poses over the
  belt, one tilted 30 degrees, checked against the description's forward kinematics. Passed
  2026-09-15: all three within 0.001 mm and 0.001 degrees.
- `ros2 launch pork_leg_cell_ros sim_grasp.launch.py arm:=ur20` (or `arm:=sr20ia`, or
  `arm:=sr20ia tool_tilt_deg:=15.0`): the whole chain against the simulated cell; the bridge logs
  the tool's miss at the meeting and the jaw opening after closing on `sim/grasp_report`.

## Not in place yet

- pick_ik is not packaged in RoboStack; the SR-20iA uses `scara_ik_node`, and the UR20 uses KDL.
- The learned grasp policy is not wired into `grasp_policy_node`.
- Real hardware: the UR ROS 2 driver (its `scaled_joint_trajectory_controller` replaces the bridge's
  action; only the controller name in `config/ur20.yaml` and `moveit_controllers.yaml` changes) and a
  FANUC driver for the SR-20iA.
